# RangeFinder — v2: Auth, Rate Limiting, Smarter Diffing

## What's new vs v1
1. **Auth support** — cookies, bearer tokens, arbitrary custom headers, so you
   can test endpoints that require a logged-in session.
2. **Rate limiting + backoff** — a token-bucket style limiter plus automatic
   backoff on 429/503, so you don't get WAF-blocked or violate program rate
   limits.
3. **Smarter diffing** — instead of just status+length, compute a similarity
   score between each response body and the baseline body. Catches cases
   where invalid/valid responses happen to be the same length but different
   content.
4. **Slug/wordlist mode** — in addition to numeric ranges, accept a wordlist
   file so `{ID}` can be a username, slug, or account identifier instead of
   an integer.
5. **Structured logging** — results go to stdout AND a JSONL file for later
   triage, with retry-aware error handling instead of silent skips.

## Usage
```
go run . \
  -url "https://target.example.com/api/users/{ID}" \
  -start 1 -end 50000 \
  -workers 20 \
  -baseline 999999999 \
  -header "Cookie: session=abc123" \
  -header "Authorization: Bearer eyJ..." \
  -rps 10 \
  -out results.jsonl

# or wordlist mode:
go run . \
  -url "https://target.example.com/account/{ID}" \
  -wordlist slugs.txt \
  -workers 20 \
  -baseline "nonexistent-account-zzz" \
  -rps 10
```

## Rate limiter (ratelimit.go)

```go
package main

import (
	"context"
	"sync"
	"time"
)

// Limiter is a simple token-bucket rate limiter with adaptive backoff.
// On repeated 429/503 responses it widens the interval between requests;
// on a run of clean responses it eases back down toward the configured rate.
type Limiter struct {
	mu          sync.Mutex
	interval    time.Duration
	baseInterval time.Duration
	lastTick    time.Time
	consecutive429 int
}

func NewLimiter(rps int) *Limiter {
	interval := time.Second / time.Duration(rps)
	return &Limiter{interval: interval, baseInterval: interval}
}

func (l *Limiter) Wait(ctx context.Context) {
	l.mu.Lock()
	wait := l.interval - time.Since(l.lastTick)
	l.lastTick = time.Now()
	l.mu.Unlock()

	if wait > 0 {
		select {
		case <-time.After(wait):
		case <-ctx.Done():
		}
	}
}

// ReportThrottled widens the interval (exponential-ish backoff, capped).
func (l *Limiter) ReportThrottled() {
	l.mu.Lock()
	defer l.mu.Unlock()
	l.consecutive429++
	l.interval = minDuration(l.interval*2, 5*time.Second)
}

// ReportOK gradually relaxes the interval back toward baseline after
// a string of clean responses.
func (l *Limiter) ReportOK() {
	l.mu.Lock()
	defer l.mu.Unlock()
	if l.consecutive429 > 0 {
		l.consecutive429 = 0
	} else if l.interval > l.baseInterval {
		l.interval = maxDuration(l.baseInterval, l.interval-10*time.Millisecond)
	}
}

func minDuration(a, b time.Duration) time.Duration {
	if a < b {
		return a
	}
	return b
}
func maxDuration(a, b time.Duration) time.Duration {
	if a > b {
		return a
	}
	return b
}
```

## Response similarity (diff.go)

```go
package main

import "strings"

// similarity returns a 0.0–1.0 score for how alike two response bodies are,
// using a cheap word-shingle Jaccard index. Good enough to catch "same
// template, different data" pages without pulling in a heavy diff library.
func similarity(a, b string) float64 {
	if a == b {
		return 1.0
	}
	sa := shingles(a, 5)
	sb := shingles(b, 5)
	if len(sa) == 0 || len(sb) == 0 {
		return 0.0
	}

	intersection := 0
	for k := range sa {
		if sb[k] {
			intersection++
		}
	}
	union := len(sa) + len(sb) - intersection
	if union == 0 {
		return 1.0
	}
	return float64(intersection) / float64(union)
}

func shingles(s string, size int) map[string]bool {
	words := strings.Fields(s)
	set := make(map[string]bool)
	if len(words) < size {
		set[strings.Join(words, " ")] = true
		return set
	}
	for i := 0; i+size <= len(words); i++ {
		set[strings.Join(words[i:i+size], " ")] = true
	}
	return set
}
```

Use this as: flag a response as interesting if `status != baseline.status`
**or** `similarity(body, baseline.body) < threshold` (e.g. 0.85). This catches
near-miss cases v1 would've silently passed over.

## Auth headers + fetcher (fetcher.go)

```go
package main

import (
	"io"
	"net/http"
	"strings"
	"time"
)

type Fetcher struct {
	client  *http.Client
	headers []string // raw "Key: Value" strings from -header flags
}

func NewFetcher(timeout time.Duration, headers []string) *Fetcher {
	return &Fetcher{
		client:  &http.Client{Timeout: timeout},
		headers: headers,
	}
}

func (f *Fetcher) Get(url string) (status int, body string, err error) {
	req, err := http.NewRequest("GET", url, nil)
	if err != nil {
		return 0, "", err
	}
	for _, h := range f.headers {
		parts := strings.SplitN(h, ":", 2)
		if len(parts) == 2 {
			req.Header.Set(strings.TrimSpace(parts[0]), strings.TrimSpace(parts[1]))
		}
	}

	resp, err := f.client.Do(req)
	if err != nil {
		return 0, "", err
	}
	defer resp.Body.Close()

	b, err := io.ReadAll(resp.Body)
	if err != nil {
		return resp.StatusCode, "", err
	}
	return resp.StatusCode, string(b), nil
}
```

## Wiring it together (main.go — delta from v1)
- Accept repeated `-header` flags (use `flag.Var` with a custom string-slice type)
- Accept `-wordlist path.txt` as an alternative to `-start/-end`; if given a
  wordlist, read it line by line and feed those strings into the same
  job-channel pattern from v1 instead of integers
- Before each fetch, call `limiter.Wait(ctx)`; after each fetch, call
  `limiter.ReportThrottled()` on 429/503 or `limiter.ReportOK()` otherwise
- Write every result (not just hits) as a JSON line to `-out` so you can
  re-analyze a run later without re-hitting the target

## Known limitations (fixed in v3)
- No config file — every run is a long CLI invocation
- No support for non-sequential ID formats like UUIDs or hashids
- No CSV/HTML report, just JSONL
- No proxy support (useful for routing through Burp to manually inspect hits)
- Single endpoint template only — can't sweep multiple endpoints in one run
