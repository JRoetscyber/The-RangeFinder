# RangeFinder — v1: Minimal Viable Fuzzer

## Goal
Prove the core loop works: iterate a sequential ID range across a single endpoint
template, send concurrent requests, and flag responses that look different from
a known "invalid ID" baseline.

This version is deliberately dumb. It will produce false positives. That's fine —
v1 is about getting the plumbing right (concurrency, HTTP handling, output) before
adding intelligence in v2/v3.

## Scope
- One target URL template with a single `{ID}` placeholder
- Numeric sequential ranges only (e.g. 1–50000)
- Fixed worker pool size
- Baseline = one known-bad ID, compared by status code + content length
- Plain stdout output

## Project layout
```
rangefinder/
```

## Usage (target UX)
```
go run main.go \
  -url "https://target.example.com/api/users/{ID}" \
  -start 1 -end 50000 \
  -workers 20 \
  -baseline 999999999
```

## Core code

```go
package main

import (
	"flag"
	"fmt"
	"io"
	"net/http"
	"strconv"
	"strings"
	"sync"
	"time"
)

type Result struct {
	ID         int
	StatusCode int
	Length     int
	Interesting bool
}

type Baseline struct {
	StatusCode int
	Length     int
}

func buildURL(template string, id int) string {
	return strings.ReplaceAll(template, "{ID}", strconv.Itoa(id))
}

func fetch(client *http.Client, url string) (int, int, error) {
	req, err := http.NewRequest("GET", url, nil)
	if err != nil {
		return 0, 0, err
	}
	resp, err := client.Do(req)
	if err != nil {
		return 0, 0, err
	}
	defer resp.Body.Close()

	body, err := io.ReadAll(resp.Body)
	if err != nil {
		return resp.StatusCode, 0, err
	}
	return resp.StatusCode, len(body), nil
}

func worker(id int, urlTemplate string, client *http.Client, baseline Baseline, results chan<- Result, wg *sync.WaitGroup) {
	defer wg.Done()

	url := buildURL(urlTemplate, id)
	status, length, err := fetch(client, url)
	if err != nil {
		return // v1: silently skip network errors, v2 will retry/log them
	}

	interesting := status != baseline.StatusCode || length != baseline.Length

	results <- Result{
		ID:          id,
		StatusCode:  status,
		Length:      length,
		Interesting: interesting,
	}
}

func main() {
	urlTemplate := flag.String("url", "", "URL template with {ID} placeholder")
	start := flag.Int("start", 1, "start of ID range")
	end := flag.Int("end", 100, "end of ID range")
	workers := flag.Int("workers", 10, "concurrent workers")
	baselineID := flag.Int("baseline", 0, "a known-invalid ID to establish baseline response")
	flag.Parse()

	if *urlTemplate == "" {
		fmt.Println("missing -url")
		return
	}

	client := &http.Client{Timeout: 10 * time.Second}

	// Establish baseline from a known-bad ID
	bStatus, bLength, err := fetch(client, buildURL(*urlTemplate, *baselineID))
	if err != nil {
		fmt.Println("failed to establish baseline:", err)
		return
	}
	baseline := Baseline{StatusCode: bStatus, Length: bLength}
	fmt.Printf("baseline -> status=%d length=%d\n", baseline.StatusCode, baseline.Length)

	ids := make(chan int, *workers)
	results := make(chan Result, *workers)
	var wg sync.WaitGroup

	// spin up worker pool
	for w := 0; w < *workers; w++ {
		go func() {
			for id := range ids {
				wg.Add(1)
				worker(id, *urlTemplate, client, baseline, results, &wg)
			}
		}()
	}

	// feed IDs
	go func() {
		for id := *start; id <= *end; id++ {
			ids <- id
		}
		close(ids)
	}()

	// close results once all work is done
	go func() {
		wg.Wait()
		close(results)
	}()

	hits := 0
	for r := range results {
		if r.Interesting {
			hits++
			fmt.Printf("[HIT] id=%d status=%d length=%d\n", r.ID, r.StatusCode, r.Length)
		}
	}
	fmt.Printf("done. %d interesting responses out of range\n", hits)
}
```

## Known limitations (fixed in v2/v3)
- No auth/cookie/header support — can't test anything behind a login
- No rate limiting — will get you WAF-blocked or banned from a program fast
- Baseline comparison is naive (status+length only) — misses cases where valid
  and invalid responses happen to be the same length
- No retry/backoff on transient network errors
- Only supports pure numeric sequential IDs, not slugs/UUIDs/hashids
- No persistent output (CSV/JSON) for later triage

## What to test this on first
Spin up a trivial local HTTP server with a few routes that return different
status/length for valid vs invalid IDs, and confirm the hit detection works
before ever pointing this at a real program.
